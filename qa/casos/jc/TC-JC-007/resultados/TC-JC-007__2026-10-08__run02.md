# TC-JC-007 — Error de API por modelo no soportado (E-04) y restablecimiento a best_match

## Datos del evaluador
- Nombre: Juan Camilo La Rotta
- Rol / bloque: QA Lead / jc
- Fecha de ejecución: 2026-10-08
- N.º de ejecución (run): 02

## Descripción del caso de prueba
- RF relacionado: RF-07
- Tipo de prueba: Funcional
- Objetivo: Verificar que, si la API responde HTTP 400 por un modelo no soportado, la aplicación muestre el mensaje E-04 y restablezca automáticamente el modelo activo a "Automático" (`best_match`).
- Precondiciones: Interceptación de red configurada para responder HTTP 400 con body `{error: true, reason: '...'}` ante un parámetro `models` no soportado (`icon_seamless`).

## Ambiente
- Nombre: QA
- URL: https://app-clima-local.vercel.app
- Commit / versión evaluada: v1.0.0
- Herramienta: Playwright

## Paso a paso ejecutado
1. Seleccionar el modelo numérico ICON (`icon_seamless`) en las Opciones Avanzadas para forzar la consulta con el parámetro `models=icon_seamless`.
2. Interceptar la solicitud de la API y devolver un error HTTP 400 (parámetros/modelo no soportado).
3. Verificar que el modelo activo en la interfaz y en la variable de estado se restablezca automáticamente a "Automático" (`best_match`).
4. Verificar la visibilidad del mensaje de error E-04 ("No fue posible procesar la consulta. Verifique los datos ingresados.") en una región `role="alert"`.

## Comando(s) de ejecución
```bash
npx playwright test qa/casos/jc/TC-JC-007/TC-JC-007.spec.ts --config=qa/playwright.config.ts --project=jc
```

## Resultado esperado
Se muestra "No fue posible procesar la consulta. Verifique los datos ingresados." (E-04) en una región `role="alert"`.
El modelo activo vuelve automáticamente a "Automático" / `best_match`.

## Resultado obtenido
La prueba se ejecutó exitosamente. Al responder la API con un error HTTP 400 tras seleccionar `icon_seamless`, la aplicación activó el fallback restableciendo automáticamente el modelo a "Automático" (`best_match`) y conservó el mensaje de error E-04 visible en la interfaz en una región `role="alert"`, sin borrarlo prematuramente tras la recarga exitosa de los datos.
