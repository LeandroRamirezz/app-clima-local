## Descripción del caso de prueba
- RF relacionado: RF-02 (Búsqueda de ciudad por nombre)
- Tipo de prueba: Funcional
- Objetivo: Verificar que la búsqueda de ciudad maneja correctamente los distintos escenarios de entrada y resultados, mostrando mensajes claros y sin romper la interfaz.
- Precondiciones: App cargada; conexión a internet; endpoint /v1/search disponible; ambiente https://app-clima-local.vercel.app operativo.

## Paso a paso ejecutado
1. Escribir «Bogotá» y validar selección y carga de clima actual.
2. Escribir «San» y validar lista de homónimos múltiples con región y país.
3. Escribir «Xyzabc123» y validar mensaje de ausencia de resultados.
4. Escribir «a» y validar mensaje de mínimo 2 caracteres.
5. Escribir «!!!» y validar mensaje de caracteres válidos.
6. Limpiar campo o enviar vacío y validar mensaje de ayuda/estabilidad.
7. Ejecutar ciclo de búsquedas consecutivas y validar operabilidad general.

## Comando(s) de ejecución
```bash
npm run qa:test:js
```

## Resultado esperado
1. «Bogotá»: muestra resultados y clima de Bogotá.
2. «San»: lista de homónimos con región y país; el usuario debe elegir.
3. «Xyzabc123»: mensaje «No se encontraron ubicaciones para «Xyzabc123». Verifique la ortografía o pruebe con otro nombre.».
4. «a» o «!!!»: mensaje «Ingrese al menos 2 caracteres válidos.».
5. Campo vacío: mensaje «Escriba el nombre de una ciudad.» / texto de ayuda visible.
6. En todos los casos, la interfaz permanece operativa.

## Resultado obtenido
5 de los 6 tests automatizados finalizaron con éxito. Falló la validación del paso con la entrada «!!!»:
La aplicación web desplegada no valida si la cadena está compuesta únicamente por símbolos o caracteres no alfanuméricos. Al ingresar «!!!», la validación en cliente consideró que la cadena tiene longitud 3 (`length >= 2`), despachó la petición hacia el endpoint de Geocoding y renderizó el mensaje de búsqueda vacía:
*«No se encontraron ubicaciones para «!!!». Verifique la ortografía o pruebe con otro nombre.»*
en lugar de advertir al usuario con el mensaje de validación estipulado:
*«Ingrese al menos 2 caracteres válidos.»*.

## Observaciones
El archivo `src/utils/city-query.ts` únicamente evalúa `[...normalized].length < CITY_QUERY_MIN_LENGTH`. Para dar cumplimiento estricto al flujo alterno de RF-02 ("Texto demasiado corto o solo símbolos: Ingrese al menos 2 caracteres válidos"), la expresión regular o lógica de validación debe descartar cadenas formadas exclusivamente por signos o caracteres especiales antes de disparar la consulta a la API externa.
