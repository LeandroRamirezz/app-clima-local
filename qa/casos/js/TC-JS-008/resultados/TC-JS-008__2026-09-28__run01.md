## Descripción del caso de prueba
- RF relacionado: RF-02 (Búsqueda de ciudad por nombre)
- Tipo de prueba: Contrato
- Objetivo: Verificar que la respuesta de /v1/search cumple con el esquema JSON esperado.
- Precondiciones: Esquema JSON definido (results array con name, latitude, longitude, country_code, admin1, timezone, elevation; y otros campos opcionales); conexión a internet activa.

## Ambiente
- Nombre: QA
- URL: https://app-clima-local.vercel.app
- Commit / versión evaluada: 2ebd149
- Herramienta: Playwright

## Paso a paso ejecutado
1. Realizar petición HTTP GET a /v1/search para la query «Bogotá» y validar contra esquema JSON Schema con Ajv.
2. Realizar petición HTTP GET a /v1/search para la query con homónimos «San» y validar contra esquema JSON Schema con Ajv.
3. Realizar petición HTTP GET a /v1/search para la query sin coincidencias «Xyzabc123» y validar contra esquema con Ajv.
4. Comprobar que mutaciones o rupturas del esquema JSON son detectadas y rechazadas por el validador Ajv como alerta temprana de regresión en el pipeline CI.

## Comando(s) de ejecución
```bash
npx playwright test --config=qa/playwright.config.ts qa/casos/js/TC-JS-008/TC-JS-008.spec.ts --project=js
```

## Resultado esperado
Para queries con resultados, la respuesta cumple el esquema. Para queries sin resultados, la respuesta no contiene "results" o es un array vacío, y también cumple el esquema esperado. Si el esquema real difiere, el pipeline falla con alerta temprana.

## Resultado obtenido
Las 4 pruebas de contrato pasaron satisfactoriamente (4/4). La respuesta de la Geocoding API de Open-Meteo cumplió al 100% con el esquema JSON Schema (Draft-07): para «Bogotá» y «San» se validaron todos los tipos y restricciones de los campos requeridos (id integer, name string, latitude y longitude en rangos geográficos válidos, admin1, country, timezone), mientras que para «Xyzabc123» se validó la estructura sin resultados. El validador Ajv confirmó además la detección inmediata de violaciones de contrato.
