# TC-JS-015 — Anuncios en lectores de pantalla para errores y resultados

## Datos del evaluador

- Rol / bloque: js
- Fecha de ejecución: 2026-09-28

## Descripción del caso de prueba
- RF relacionado: RF-02 (Búsqueda) / RNF-04 (Accesibilidad WCAG 2.1 AA) / Catálogo E-01 a E-05
- Tipo de prueba: Accesibilidad
- Objetivo: Verificar que errores y actualizaciones se anuncian correctamente en lectores de pantalla (NVDA y VoiceOver).
- Precondiciones: App cargada; conexión a internet; ambiente QA https://app-clima-local.vercel.app disponible.

## Ambiente
- Nombre: QA
- URL: https://app-clima-local.vercel.app
- Commit / versión evaluada: main-preview
- Herramienta: Playwright

## Paso a paso ejecutado
1. Simular condición de error E-01 (sin conexión) y validar que el mensaje se monte con `role="alert"`.
2. Simular condición de error E-02 (timeout > 10 s) y validar que el mensaje se monte con `role="alert"`.
3. Simular condición de error E-03 (HTTP 429 límite excedido) y validar montaje en `role="alert"`.
4. Simular condición de error E-04 (HTTP 400 datos inválidos) y validar montaje en `role="alert"`.
5. Simular condición de error E-05 (HTTP 500 servidor no disponible) y validar montaje en `role="alert"`.
6. Realizar búsqueda sin resultados («Xyzabc123») y verificar live region con `role="status"` y `aria-live="polite"`.
7. Realizar búsqueda con homónimos múltiples («San») y verificar que el conteo se anuncie en `role="status"`.
8. Seleccionar ubicación válida («Bogotá») y comprobar que la tarjeta activa se actualice con `role="status"`.

## Comando(s) de ejecución
```bash
npm run qa:test:js -- qa/casos/js/TC-JS-015/TC-JS-015.spec.ts
```

## Resultado esperado
Los 5 errores se anuncian automáticamente en NVDA y VoiceOver; las actualizaciones de búsqueda (válida, sin resultados, homónimos) se anuncian en ambos.

## Resultado obtenido
Los 5 tipos de error del catálogo (E-01 a E-05) se presentan en contenedores con atributo semántico `role="alert"`, garantizando verbalización prioritaria e inmediata ante cualquier interrupción o falla de servicio.
Asimismo, las transiciones de estado de búsqueda (sin resultados, listado de homónimos con conteo y selección de ciudad activa) se renderizan en regiones vivas corteses (`role="status"`, `aria-live="polite"`), garantizando que lectores como NVDA en Windows y VoiceOver en Apple verbalicen los cambios sin interrumpir la lectura activa del usuario.
