# TC-SS-008 — Categoría del AQI en valores límite, interpretación y no dependencia exclusiva del color

## Datos del evaluador
- Nombre: Sara Sofía González Gómez
- Rol / bloque: ss
- Fecha de ejecución: 2026-09-28
- N.º de ejecución (run): 01

## Descripción del caso de prueba
- RF relacionado: RF-06 (Calidad del aire), S-02 (escala US AQI)
- Tipo de prueba: Funcional
- Objetivo: Verificar, con análisis de valores límite, que cada valor de us_aqi se asigne a la categoría correcta de la escala de EE. UU. (S-02), con texto, color, ícono y mensaje de salud, y que los valores fuera de rango se traten según el flujo alterno.
- Precondiciones: Ubicación activa: Neiva. Interceptación de /v1/air-quality con Playwright que devuelve el valor de current.us_aqi bajo prueba. Emulación de acromatopsia de Chrome (CDP Emulation.setEmulatedVisionDeficiency).

## Ambiente
- Nombre: QA
- URL: https://app-clima-local.vercel.app
- Commit / versión evaluada: 66860ed (origin/main)
- Herramienta: Playwright 1.63.0 (Chromium build 1243)

## Datos de entrada
current.us_aqi = 0, 50, 51, 100, 101, 150, 151, 200, 201, 300, 301, 500, -1, "abc".

## Paso a paso ejecutado
0. Seleccionar Neiva, Huila como ubicación activa. Interceptar /v1/air-quality con Playwright y reemplazar current.us_aqi por el valor bajo prueba (un test por valor).
1. Para cada valor (0, 50, 51, 100, 101, 150, 151, 200, 201, 300, 301, 500, -1, "abc"), abrir la pestaña «Calidad del aire».
2. Anotar el número mostrado, la categoría en texto, el color (clase CSS), el ícono y el mensaje.
3. Verificar si existe un ícono y si tiene texto alternativo (alt o aria-label).
4. Con el valor 151, activar la emulación «Achromatopsia» (CDP Emulation.setEmulatedVisionDeficiency, equivalente a DevTools > Rendering) y verificar si la categoría se entiende por texto e ícono.

## Comando(s) de ejecución
```bash
npx playwright test --config=qa/playwright.config.ts qa/casos/ss/TC-SS-008 --project=ss
```

## Resultado esperado
- 0 y 50 → «Buena»
- 51 y 100 → «Moderada»
- 101 y 150 → «Dañina para grupos sensibles»
- 151 y 200 → «Dañina»
- 201 y 300 → «Muy dañina»
- 301 y 500 → «Peligrosa»
- -1 y "abc" → «N/D» (sin categoría)

En los valores válidos, el número siempre va acompañado de categoría en texto, ícono con alternativa textual, color y mensaje de salud breve. En escala de grises la categoría sigue identificándose por texto e ícono.

## Observaciones
1. El ícono faltante es el mismo defecto reportado en TC-SS-007 (BUG-SS-002); se referencia sin duplicarlo.
2. El comportamiento con "abc" se registró como BUG-SS-003 por decisión de la evaluadora.
3. Con -1 la app muestra el número «-1» junto a la categoría «N/D»; se considera conforme porque el flujo alterno de RF-06 habla de la categoría.
4. Los mensajes de categoría interpretan el rango pero no dan una recomendación de salud (ver observación de TC-SS-007).
5. El mock usa la respuesta real de /v1/air-quality y solo reemplaza `current.us_aqi`.
