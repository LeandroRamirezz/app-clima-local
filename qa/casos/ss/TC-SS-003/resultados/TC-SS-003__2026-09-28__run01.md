## Descripción del caso de prueba
- RF relacionado: RF-05 (Datos históricos)
- Tipo de prueba: Funcional
- Objetivo: Verificar, con análisis de valores límite, que el sistema acepte solo fechas entre 01/01/1940 y la última fecha disponible (hoy menos el margen de 5 días), muestre el mensaje exacto para cada fecha fuera de rango y no envíe la solicitud a la API cuando la fecha es inválida.
- Precondiciones: Ubicación activa: Neiva. Fecha del sistema: 28/09/2026 (día de ejecución); margen de disponibilidad de 5 días, última fecha consultable = 23/09/2026. Solicitudes de red registradas con Playwright (equivalente a DevTools > Network).

## Observaciones
1. Por indicación de la evaluadora, se usó la fecha real del día de ejecución (28/09/2026, reloj del navegador en America/Bogota) en lugar de la del diseño (27/09/2026). Las fechas se desplazaron con los mismos offsets del diseño.
2. En 01/01/1940 la precipitación se muestra como «N/D» porque la API devuelve `precipitation_sum = [null]` para esa fecha (verificado con una consulta directa: `respuesta-directa-1940-01-01.json`). Es el manejo correcto de nulos, no un defecto.
