## Descripción del caso de prueba
- RF relacionado: RNF-14 (Disponibilidad / Hosting HTTPS), RF-03 (requisito de contexto seguro)
- Tipo de prueba: Seguridad
- Objetivo: Verificar que la aplicación se sirva completamente por HTTPS, que el acceso por HTTP redirija a HTTPS y que las solicitudes a los 4 endpoints de Open-Meteo usen HTTPS, sin contenido mixto (requisito además para la geolocalización de RF-03).
- Precondiciones: Ambiente desplegado https://app-clima-local.vercel.app. curl 8 y openssl (Git Bash) disponibles. Playwright con Chromium completo para registrar solicitudes, consola y estado de seguridad (equivalente a DevTools > Network, Console y Security).

## Ambiente
- Nombre: QA
- URL: https://app-clima-local.vercel.app
- Commit / versión evaluada: 66860ed (origin/main)
- Herramienta: Playwright 1.63.0 (Chromium completo) + curl + openssl

## Datos de entrada
- URL: https://app-clima-local.vercel.app (y http://app-clima-local.vercel.app para la redirección).
- Flujo: buscar «Bogotá», ver pronóstico, abrir histórico (15/09/2026), calidad del aire y comparar con Neiva.

## Paso a paso ejecutado
1. Ejecutar curl -I http://app-clima-local.vercel.app y verificar el código y la cabecera Location.
2. Ejecutar curl -I https://app-clima-local.vercel.app y verificar HTTP 200; verificar el certificado con openssl s_client (sujeto, emisor, vigencia y código de verificación).
3. Abrir la app en Chromium (Playwright, Chromium completo en modo headless) y recorrer el flujo: buscar «Bogotá», ver pronóstico, abrir histórico (15/09/2026), calidad del aire y comparar Bogotá con Neiva.
4. Registrar todas las solicitudes del flujo (equivalente a DevTools > Network) y verificar que usen https://, incluidas las de los 4 endpoints de Open-Meteo.
5. Revisar los mensajes de consola buscando advertencias de «Mixed Content».
6. Leer el estado de seguridad de la página con el dominio Security de DevTools (CDP Security.visibleSecurityStateChanged, equivalente a la pestaña Security) y window.isSecureContext.

## Comando(s) de ejecución
```bash
curl -I http://app-clima-local.vercel.app
curl -I https://app-clima-local.vercel.app
openssl s_client -connect app-clima-local.vercel.app:443 -servername app-clima-local.vercel.app | openssl x509 -noout -subject -issuer -dates -ext subjectAltName
npx playwright test --config=qa/playwright.config.ts qa/casos/ss/TC-SS-015 --project=ss
```

## Resultado esperado
- http:// responde 301 o 308 con Location: https://app-clima-local.vercel.app
- https:// responde 200 con certificado válido, sin advertencias.
- 100 % de las solicitudes del flujo usan HTTPS (incluidas las 4 de Open-Meteo).
- 0 advertencias de contenido mixto. La página se reporta como segura.

## Observaciones
1. El diseño lista dos veces «curl -I https://…»; siguiendo el paso 1 se usó http:// en el primer comando.
2. El código 308 (en lugar de 301) cumple el criterio; la cabecera Location incluye la barra final, equivalente a la URL esperada.
3. El estado de la pestaña Security se leyó con el dominio Security de DevTools; se usó el Chromium completo de Playwright (`channel: 'chromium'`) porque el shell headless por defecto no emite esos eventos.
4. curl en Windows (schannel) no imprime los datos del certificado; se complementó con openssl.
