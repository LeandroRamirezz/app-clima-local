# TC-SS-013 — Persistencia de la preferencia de unidades: recarga, valor corrupto y localStorage no disponible

## Datos del evaluador
- Nombre: Sara Sofía González Gómez
- Rol / bloque: ss
- Fecha de ejecución: 2026-09-29
- N.º de ejecución (run): 01

## Descripción del caso de prueba
- RF relacionado: RF-10 (Conversión de unidades), RNF-07 (Privacidad)
- Tipo de prueba: Funcional
- Objetivo: Verificar que la preferencia de unidades se guarde en localStorage y se aplique al volver a abrir la app; que un valor alterado o inválido se ignore y se restablezcan los valores por defecto; que la app funcione sin error si localStorage no está disponible, y que solo se guarden unidades (sin coordenadas ni datos de clima).
- Precondiciones: Ambiente QA. Clave de preferencias validada en el código: "weather-app.units". Contenido de localStorage leído con Playwright (equivalente a DevTools > Application > Local Storage). Script de inicio (addInitScript) que hace fallar localStorage.getItem y setItem para el escenario D.

## Ambiente
- Nombre: QA
- URL: https://app-clima-local.vercel.app
- Commit / versión evaluada: 66860ed (origin/main)
- Herramienta: Playwright 1.63.0 (Chromium build 1243)

## Datos de entrada
- A: guardar °F / mph / in.
- B (corrupto): valor de la clave = `abc{` (JSON inválido).
- C (inválido): valor = `{"temperatura":"kelvin","viento":"nudos","precipitacion":"cm"}`.
- D: localStorage que lanza SecurityError al leer o escribir.

## Paso a paso ejecutado
0. Validar en el código la clave de preferencias: FORECAST_UNITS_STORAGE_KEY = "weather-app.units" (src/config/forecast.ts), con formato {"temperature","windSpeed","precipitation"}.
1. Escenario A: seleccionar Neiva, cambiar a °F / mph / in, recargar la página (F5), volver a seleccionar Neiva y verificar el selector y la solicitud a /v1/forecast.
2. Cerrar la pestaña, abrir la app en una pestaña nueva (mismo navegador), seleccionar Neiva y verificar de nuevo.
3. Revisar todo el contenido de localStorage (y sessionStorage) con una ubicación y datos de clima cargados.
4. Escenario B: escribir "abc{" en la clave, recargar, seleccionar Neiva y verificar unidades, errores y el valor de la clave; luego cambiar de unidad y verificar que la clave se sobrescribe.
5. Escenario C: escribir {"temperatura":"kelvin","viento":"nudos","precipitacion":"cm"} en la clave y repetir la verificación del paso 4.
6. Escenario D: cargar la app con un script de inicio (addInitScript) que hace lanzar SecurityError a localStorage.getItem y setItem; seleccionar Neiva, cambiar a °F / mph / in y recargar.
7. En todos los escenarios revisar la consola (pageerror y console.error).

## Comando(s) de ejecución
```bash
npx playwright test --config=qa/playwright.config.ts qa/casos/ss/TC-SS-013 --project=ss
```

## Resultado esperado
- A: tras la recarga y en una pestaña nueva se aplican °F / mph / in. localStorage contiene solo la preferencia de unidades, sin coordenadas, nombres de ciudad ni datos de clima.
- B y C: el valor se ignora, la app carga con °C / km/h / mm sin error visible y la clave queda corregida o sobrescrita al cambiar de unidad.
- D: la app funciona con las unidades por defecto; el cambio de unidad funciona durante la sesión; no aparece un error visible ni una excepción no controlada en consola.

## Observaciones
1. Cada escenario se ejecutó en un contexto de navegador nuevo; A usa una segunda pestaña del mismo contexto para el paso 2.
2. La ubicación no se persiste, por lo que después de cada recarga se vuelve a seleccionar Neiva para observar la solicitud a /v1/forecast.
3. En B y C la app reescribe la clave con los valores por defecto al cargar, antes de cualquier cambio del usuario.
4. El escenario D se simuló reemplazando `Storage.prototype.getItem` y `setItem` con funciones que lanzan `DOMException` «SecurityError»; la app captura el error y no registra nada en consola.
