# Corrección BUG-004 — E-04 desaparecía después del fallback de modelo

- **Hallazgo QA:** TC-JC-007, reportado el 28/09/2026 sobre el build `66860ed`. ICON (`icon_seamless`) recibió HTTP 400 y Forecast volvió correctamente a `best_match`, pero el mensaje E-04 desapareció al finalizar la consulta de respaldo.
- **Causa:** los callbacks `onSuccess` de los flujos Forecast borraban `modelFallbackError` tras cualquier respuesta exitosa, incluso la primera respuesta de Automático posterior al error del modelo seleccionado.
- **Corrección:** se eliminó ese borrado automático y el callback que solo lo ejecutaba. E-04 permanece visible en `role="alert"` mientras el panel vuelve a mostrar los datos de Automático. Una nueva selección explícita en el control de modelo limpia el aviso antes de consultar el modelo elegido. El fallback automático y la protección contra respuestas obsoletas permanecen intactos.
- **Seguridad del mensaje:** se presenta el texto seguro de E-04; no se muestra `reason` crudo de Open-Meteo.
- **Regresión:** la prueba de componente verifica ICON HTTP 400, una sola consulta de respaldo a `best_match`, datos visibles, E-04 persistente y limpieza al elegir después otro modelo. La prueba E2E intercepta `/v1/forecast` en Chromium y comprueba E-04 tras el fallback exitoso.
- **Verificación local:** `npm test`: 16 archivos y 353/353 pruebas aprobadas. `npm run lint`: salida 0. `npm run build`: salida 0, TypeScript y Vite correctos. `npm run test:e2e`: 5/5 aprobadas. Auditoría estática de UI en modo estricto: 0 hallazgos.
- **Documentación anterior:** los documentos entregados a QA permanecen sin cambios. Esta nota documenta la corrección posterior.

**Estado de corrección:** implementada y verificada localmente. QA debe repetir TC-JC-007 en el build actualizado para cerrar el hallazgo de forma independiente.
