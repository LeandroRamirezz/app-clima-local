# Corrección BUG-002 — Reintentar visible después de HTTP 429

- **Hallazgo QA:** TC-JC-004, reportado el 28/09/2026 en el flujo de pronóstico para Neiva.
- **Comportamiento reportado:** `/v1/forecast` devolvía HTTP 429; el mensaje E-03 se mostraba correctamente, pero seguía visible el botón `Reintentar`.
- **Causa raíz:** el panel de error de Forecast renderizaba el botón para todos los códigos E-01 a E-05 sin distinguir E-03. Aunque el servicio clasificaba correctamente HTTP 429, esa clasificación no condicionaba la presentación de `Reintentar`.
- **Corrección:** el panel conserva el mensaje seguro E-03 en `role="alert"` y no renderiza el botón de reintento para ese código. E-01, E-02, E-04 y E-05 mantienen su reintento manual. No se agregan reintentos automáticos ante HTTP 429.
- **Pruebas de regresión:** prueba del componente que comprueba mensaje, ausencia del botón y una sola consulta; prueba E2E en Chromium que intercepta `/v1/forecast` con HTTP 429 y comprueba el mismo comportamiento en la interfaz.
- **Verificación local:** `npm test`: 16 archivos, 351/351 pruebas aprobadas. `npm run lint`: código de salida 0. `npm run build`: código de salida 0, TypeScript y Vite correctos. `npm run test:e2e`: 3/3 pruebas aprobadas, incluida BUG-002.
- **Documentación anterior:** los documentos entregados a QA permanecen sin cambios. Esta nota documenta una corrección posterior.

**Estado de corrección:** implementada y verificada localmente. QA debe repetir TC-JC-004 en el build actualizado para cerrar el hallazgo de forma independiente.
