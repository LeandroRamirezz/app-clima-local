# Corrección BUG-001 — Búsqueda compuesta solo por símbolos

- **Hallazgo QA:** TC-JS-001, reportado el 27/09/2026 sobre el build `66860ed`.
- **Comportamiento reportado:** `!!!` generaba una solicitud a `/v1/search` y mostraba un estado sin resultados.
- **Causa:** la validación compartida exigía dos caracteres Unicode, pero contaba símbolos como si fueran letras válidas.
- **Corrección:** `validateCityQuery` exige al menos dos letras Unicode dentro del límite existente de 100 caracteres. Conserva el texto original para nombres legítimos con espacios, tildes o puntuación; no elimina caracteres arbitrariamente. El buscador presenta `Ingrese al menos 2 caracteres válidos.` después del debounce y el servicio rechaza una invocación directa inválida antes de llamar a `fetch`.
- **Regresión automatizada:** se agregó el caso visible `!!!` al componente y se ampliaron los casos del servicio con `!!!` y `A!`, comprobando que no se envía ninguna petición. La prueba preexistente de `São Paulo & Cía` sigue cubriendo caracteres especiales válidos.
- **Verificación local:** `npm test`: 16 archivos aprobados; 351/351 pruebas aprobadas. `npm run lint`: código de salida 0. `npm run build`: código de salida 0; compilación TypeScript y Vite correctas.
- **Incidencia durante la verificación:** una primera ejecución de `npm test` en paralelo con lint y build falló en una prueba de carga diferida de Históricos (350/351); la ejecución completa posterior, sin esa concurrencia, pasó 351/351. No se cambió esa prueba ni su funcionalidad.
- **Documentación de entrega anterior:** permanece sin modificaciones. Esta nota registra la corrección posterior al traspaso.

**Estado de corrección:** implementada y verificada localmente. QA debe volver a ejecutar TC-JS-001 en el build actualizado para cerrar el hallazgo de manera independiente.
