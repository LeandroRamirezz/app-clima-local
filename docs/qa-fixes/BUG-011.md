# Corrección BUG-011 — Cabeceras de seguridad en Vercel

- **Hallazgo QA:** TC-SS-016, reportado el 28/09/2026 sobre el build `70837c6`. La respuesta pública no incluía `Content-Security-Policy`, `X-Content-Type-Options` ni `Referrer-Policy`.
- **Causa raíz:** `vercel.json` contenía únicamente la reescritura de rutas de la aplicación estática. No declaraba reglas `headers`, por lo que Vercel enviaba su HSTS de plataforma, pero no las tres cabeceras exigidas por RNF-06. Antes del cambio se confirmó con una solicitud `HEAD` a la URL pública: HTTP 200, las tres cabeceras ausentes y HSTS presente.
- **Corrección:** se añadió una regla de cabeceras para `/(.*)`, aplicable al documento y a los recursos estáticos. La CSP usa `default-src 'self'`, restringe scripts, estilos, imágenes y fuentes al propio sitio, impide objetos y marcos externos, y permite `connect-src` solo a `'self'` y a los cuatro orígenes utilizados por Forecast, Geocoding, Archive y Air Quality. No contiene `unsafe-inline` ni `unsafe-eval`. Se añadieron `X-Content-Type-Options: nosniff` y `Referrer-Policy: strict-origin-when-cross-origin`.
- **Pruebas añadidas:** `src/config/deployment-headers.test.ts` comprueba las directivas clave, la lista exacta de orígenes de conexión, la ausencia de las dos excepciones inseguras y los valores de las otras dos cabeceras.
- **Verificación local:** `npm test`: 17 archivos y 374/374 pruebas aprobadas. `npm run lint`: salida 0. `npm run build`: salida 0 (`tsc -b` y Vite). `npm run test:e2e`: 11/11 aprobadas. El primer intento de build detectó que la prueba nueva importaba `node:fs` desde `src`; se corrigió importando el JSON directamente y se repitieron build, tests y lint con éxito.
- **Verificación del despliegue:** después del commit `3c461ea`, `GET /` devolvió HTTP 200 y las tres cabeceras con los valores configurados. `HEAD /assets/index-BNdiu-FD.js` devolvió HTTP 200, `Content-Type: application/javascript; charset=utf-8` y las mismas tres cabeceras. En Microsoft Edge sobre la URL publicada, React cargó, las cuatro conexiones permitidas respondieron HTTP 200 con respuestas de prueba interceptadas, una conexión a `https://example.com` fue bloqueada y no se registraron violaciones CSP para los cuatro orígenes permitidos.
- **Límite de evidencia:** no se repitieron OWASP ZAP ni Mozilla Observatory; QA puede volver a ejecutarlos sobre el despliegue actual. Esta corrección no cambia servicios ni datos meteorológicos.

La configuración de cabeceras sigue el formato oficial de [Vercel](https://vercel.com/docs/project-configuration/vercel-json). La restricción de conexiones corresponde a [`connect-src`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/connect-src), y `nosniff` a [X-Content-Type-Options](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Content-Type-Options).

Los documentos de QA ya entregados en `docs/testing/` no se modifican. QA debe repetir TC-SS-016 sobre la versión publicada para cerrar el hallazgo de forma independiente.
