# Corrección BUG-010 — Últimos datos tras fallar el cambio de unidades

- **Hallazgo QA:** TC-SS-012, reportado el 28/09/2026 sobre el build `70837c6`. Al cambiar de °C a °F, un HTTP 500 de Forecast mostraba E-05 y Reintentar, pero desaparecían el clima actual y el pronóstico obtenidos previamente en °C.
- **Causa raíz:** `useCurrentWeather` representaba el resultado como una unión excluyente de estados. Al rechazar la reconsulta, sustituía `success` por `error` y descartaba el acceso al último `ForecastData` correcto. `CurrentWeather` renderizaba clima y pronóstico solo cuando `status === 'success'`, de modo que no podía mostrar datos anteriores con sus unidades originales.
- **Corrección:** el hook conserva una referencia al último Forecast exitoso con su ubicación, rango y modelo. Si falla una reconsulta motivada por unidades para la misma ubicación, rango y modelo, el estado de error incluye esa respuesta anterior. La pantalla muestra E-01 a E-05 según corresponda y presenta clima y pronóstico usando **las unidades de la respuesta conservada**, con un aviso explícito. Reintentar sigue disponible para E-01, E-02, E-04 y E-05; E-03 mantiene su restricción de reintento. La selección nueva permanece en el control y Reintentar solicita esa configuración. Durante la carga, los datos anteriores no se presentan como si ya estuvieran convertidos. Una ubicación, rango o modelo diferente no recibe esos datos conservados.
- **Pruebas añadidas y ajustadas:** prueba de componente para E-05 con clima y pronóstico en °C tras fallar °F, seguida de reintento exitoso; verificación de que un cambio de ubicación no muestra datos ajenos; la prueba existente de fallo E-01 ahora comprueba la conservación correcta en °C y la ausencia de etiquetado falso en °F. Reproducción E2E de TC-SS-012 con HTTP 500 interceptado solo en la primera consulta °F.

Prueba E2E específica de BUG-010: 1/1 aprobada. Auditoría estática de interfaz en modo estricto: 0 hallazgos.
